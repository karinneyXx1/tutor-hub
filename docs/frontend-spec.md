# Интерфейс: выдача домашнего задания

Спецификация поведения основного сценария. Внешний вид — по макету (см. отчёт практики 8), поведение — по этому документу. Каждый пункт проверяется тестом (в скобках).

## Сценарий

Репетитор входит → видит список выданных ДЗ → нажимает «Выдать задание» → заполняет форму в диалоге → нажимает «Выдать задание» → диалог закрывается, новое задание появляется в списке, вверху сообщение «Задание «…» выдано: <ученик>».

## Вход

1. Email и пароль обязательны; email проверяется по формату `name@example.com`. (`LoginForm.test.tsx`)
2. Неверные данные (401) → «Неверный email или пароль», введённый email остаётся. (`LoginForm.test.tsx`)
3. Токен хранится в `localStorage`; после перезагрузки сессия восстанавливается через `GET /api/auth/me`, недействительный токен удаляется. (`App.test.tsx`)

## Список заданий

4. Пока идёт загрузка — три скелетона карточек и скрытый текст «Загружаем задания…» для экранного диктора.
5. Пустой список — «Пока нет заданий» и кнопка «Выдать первое задание».
6. Ошибка загрузки — «Не удалось загрузить задания», причина и кнопка «Повторить»; нет связи — «Нет связи с сервером».
7. Карточка: название, ученик, срок («до 20 ноября 2026 г.»), статус (Выдано / Сдано / На доработке / Проверено).
8. Если у репетитора нет учеников — подсказка, кнопка «Выдать задание» недоступна. Ученик видит свои ДЗ без кнопки.

(п. 4–8: `HomeworkPage.test.tsx`, «Список заданий: состояния»)

## Форма «Новое домашнее задание»

9. Поля: Ученик (обязательно), Название (обязательно, не из одних пробелов, до 200 символов), Описание (необязательно, до 5000), Срок сдачи (обязательно, не раньше сегодняшнего дня). Правила совпадают с `backend/app/schemas.py`.
10. При ошибке валидации сообщение выводится под полем, поле помечается `aria-invalid`, фокус переходит на первое поле с ошибкой, запрос не отправляется. Сообщение исчезает, когда поле исправляют.
11. Каждое открытие диалога — с пустой формы. Закрытие: «Отмена», крестик, Escape.
12. Во время сохранения кнопка заблокирована и показывает «Сохраняем…»; повторный клик, двойной клик и Enter не создают второй запрос (защита на `ref` в `useSingleFlight` + `disabled`); диалог нельзя закрыть.
13. Успех — диалог закрывается, задание появляется в списке (по сроку), сообщение об успехе в `role="status"`.
14. Срок отклонён сервером (422) — ошибка у поля «Срок сдачи». Другая ошибка сервера — сообщение вверху формы. В обоих случаях введённые данные сохраняются, можно исправить и отправить снова.

(п. 9–14: `HomeworkPage.test.tsx`, «Диалог», «Валидация формы», «Отправка формы»; браузер: `e2e/homework.spec.ts`)

## Доступность

15. У всех полей есть `<label>`; ошибки связаны с полем через `aria-describedby`.
16. Весь сценарий проходится с клавиатуры; у кнопок и полей виден индикатор фокуса (кольцо цвета `--ring`). (`e2e/homework.spec.ts`)
17. На ширине 375 px нет горизонтальной прокрутки, все поля и кнопки формы доступны. (`e2e/homework.spec.ts`)
